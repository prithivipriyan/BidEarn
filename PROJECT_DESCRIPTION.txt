1. EXECUTIVE SUMMARY & OVERVIEW
================================================================================
BidEarn is a full-stack real-time auction and e-commerce marketplace web 
application. It allows users to browse live and upcoming auctions, place competitive 
bids, track items in a personal watchlist, and list their own items for sale as a 
verified seller using a unified account model (dual buyer/seller capability). 
The platform features an administrative portal with comprehensive moderation tools, 
including listing approvals, auction termination, user management, and platform metrics.

Key Highlights:
- Dual-role capability for registered customers (bid on auctions and list items for sale).
- Real-time bidding engine with validation (minimum bid increments, anti-self-bidding).
- Multi-state auction lifecycle: PENDING -> ACTIVE -> CLOSED (SOLD / UNSOLD) or TERMINATED.
- Automated and admin-controlled moderation workflows.
- Rich image handling (local disk streaming via file API and multipart file uploads).
- Dedicated Administrator Dashboard for user auditing and auction moderation.
- Curated luxury theme: Warm White, Rich Espresso (#4A2C1A), and Antique Gold (#C49A4A).

4. DATABASE DESIGN & DATA MODELS (ENTITY RELATIONSHIP)
================================================================================

The application uses MySQL relational database with JPA / Hibernate ORM.

4.1 USERS TABLE (`users`)
- userId (BIGINT, PRIMARY KEY, AUTO_INCREMENT)
- fullName (VARCHAR(150), NOT NULL)
- email (VARCHAR(150), NOT NULL, UNIQUE, case-insensitive lookup)
- password (VARCHAR(255), NOT NULL, JSON WRITE_ONLY - never sent to client)
- country (VARCHAR(255))
- phoneNumber (VARCHAR(255))
- profilePhoto (VARCHAR(255))
- role (VARCHAR(20), NOT NULL, Enum: 'CUSTOMER', 'ADMIN', default: 'CUSTOMER')
- status (VARCHAR(20), NOT NULL, Enum: 'ACTIVE', 'SUSPENDED', default: 'ACTIVE')
- createdAt (DATETIME, updatable = false)

4.2 ITEMS TABLE (`items`)
- itemId (BIGINT, PRIMARY KEY, AUTO_INCREMENT)
- name (VARCHAR(200), NOT NULL)
- description (VARCHAR(2000))
- category (VARCHAR(255))
- imageUrl (VARCHAR(255))

4.3 AUCTIONS TABLE (`auctions`)
- auctionId (BIGINT, PRIMARY KEY, AUTO_INCREMENT)
- item_id (BIGINT, FOREIGN KEY -> items.itemId, NOT NULL)
- seller_id (BIGINT, FOREIGN KEY -> users.userId, NOT NULL)
- startingPrice (DECIMAL(12, 2), NOT NULL)
- currentPrice (DECIMAL(12, 2), NOT NULL)
- startTime (DATETIME, NOT NULL)
- endTime (DATETIME, NOT NULL)
- status (VARCHAR(20), NOT NULL, Enum: 'PENDING', 'ACTIVE', 'CLOSED', 'SOLD', 'UNSOLD', 'TERMINATED', default: 'PENDING')

4.4 BIDS TABLE (`bids`)
- bidId (BIGINT, PRIMARY KEY, AUTO_INCREMENT)
- auction_id (BIGINT, FOREIGN KEY -> auctions.auctionId, NOT NULL)
- user_id (BIGINT, FOREIGN KEY -> users.userId, NOT NULL)
- amount (DECIMAL(12, 2), NOT NULL)
- bidTime (DATETIME, NOT NULL)

4.5 WATCHLIST TABLE (`watchlist`)
- watchlistId (BIGINT, PRIMARY KEY, AUTO_INCREMENT)
- user_id (BIGINT, FOREIGN KEY -> users.userId, NOT NULL)
- auction_id (BIGINT, FOREIGN KEY -> auctions.auctionId, NOT NULL)
- addedAt (DATETIME, NOT NULL)
- Unique Constraint: `(user_id, auction_id)` prevents duplicate bookmarks.

RELATIONSHIPS:
- User (1) ---- (N) Auction [as Seller]
- User (1) ---- (N) Bid [as Bidder]
- User (1) ---- (N) Watchlist
- Item (1) ---- (N) Auction
- Auction (1) ---- (N) Bid
- Auction (1) ---- (N) Watchlist

5. CORE BUSINESS LOGIC & DOMAIN RULES
================================================================================

5.1 USER & AUTHENTICATION RULES
- Registration: Only allowed to create accounts with role 'CUSTOMER'.
- Email Uniqueness: Case-insensitive unique check before registration.
- Passwords: Encrypted using BCrypt (with fallback check for plain-text entries).
- Suspended Users: Blocked from logging into the platform (`InvalidCredentialsException`).
- Admin Access: Default administrator seeded automatically on application boot (`admin@bidearn.com`).
- Profile Management: Authenticated users can update full name, phone number, country, and avatar photo.
- Password Changing: Requires valid current password and at least 6 characters for the new password.
- Account Deletion: Cascading cleanup removes user's watchlist entries, bids, seller auctions, items, and finally user record.

5.2 AUCTION LIFECYCLE & MODERATION
- Creation:
  * Sellers specify item details, category, images, starting bid, and start/end time.
  * Validation: End time must be strictly after start time.
  * Initial status defaults to `PENDING` (awaiting administrative approval).
  * Current price is initialized to starting price.
- Moderation Approval:
  * Administrator reviews pending listings and triggers approval (`PENDING` -> `ACTIVE`).
- Auction States:
  * `PENDING`: Created by seller, awaiting admin approval.
  * `ACTIVE`: Approved. Can be in future (Upcoming) or ongoing (Live).
  * `CLOSED`: Completed auction. Marked `SOLD` if bids > startingPrice, or `UNSOLD` if no bids placed.
  * `TERMINATED`: Manually terminated by Administrator for policy violations.

5.3 BIDDING RULES & CONSTRAINTS
- Status Validation: Auction must have status `ACTIVE`.
- Time Window Validation:
  * Current time must be after auction's `startTime`.
  * Current time must be before auction's `endTime`.
- Anti-Self-Bidding: Sellers are strictly prohibited from bidding on their own listings (`SelfBidException`).
- Amount Validation: Bid amount must be strictly greater than the current leading price (`BidTooLowException`).
- Real-time Price Update: Successful bid updates auction's `currentPrice` atomically in the database.

5.4 WATCHLIST FUNCTIONALITY
- Users can bookmark any auction.
- Duplicate prevention: Attempting to add the same auction twice triggers `AlreadyInWatchlistException`.
- Users can toggle or remove items from their watchlist at any time.

6. REST API SPECIFICATIONS & ENDPOINTS
================================================================================

6.1 USER CONTROLLER (`/api/users`)
- POST   /api/users/register
         Request: User object (fullName, email, password, country, phoneNumber)
         Response: Created User (HTTP 200)
- POST   /api/users/login
         Request: { "email": "...", "password": "..." }
         Response: User object without password (HTTP 200)
- GET    /api/users/{id}
         Response: User profile by ID (HTTP 200)
- GET    /api/users
         Response: List of all users in database (HTTP 200)
- GET    /api/users/customers
         Response: List of users where role = 'CUSTOMER' (HTTP 200)
- PUT    /api/users/{id}/status?status={ACTIVE|SUSPENDED}
         Response: Updated User object (HTTP 200)
- PUT    /api/users/{id}
         Request: User updates (fullName, country, phoneNumber)
         Response: Updated User object (HTTP 200)
- PUT    /api/users/{id}/photo
         Request: { "photoUrl": "..." }
         Response: Updated User object (HTTP 200)
- POST   /api/users/forgot-password
         Request: { "email": "...", "newPassword": "..." }
         Response: { "message": "Password updated successfully" } (HTTP 200)
- PUT    /api/users/{id}/password
         Request: { "currentPassword": "...", "newPassword": "..." }
         Response: { "message": "Password changed successfully" } (HTTP 200)
- DELETE /api/users/{id}
         Response: HTTP 204 No Content (Cascading deletion)

6.2 AUCTION CONTROLLER (`/api/auctions`)
- POST   /api/auctions
         Request: Auction object (item, seller, startingPrice, startTime, endTime)
         Response: Created Auction with status = PENDING (HTTP 200)
- GET    /api/auctions
         Response: List of all auctions with joined item and seller (HTTP 200)
- GET    /api/auctions/{id}
         Response: Single auction with joined details (HTTP 200)
- GET    /api/auctions/active
         Response: Auctions where status = ACTIVE (HTTP 200)
- GET    /api/auctions/live
         Response: Auctions where status = ACTIVE and startTime <= now <= endTime (HTTP 200)
- GET    /api/auctions/upcoming
         Response: Auctions where status = ACTIVE and startTime > now (HTTP 200)
- GET    /api/auctions/pending
         Response: Auctions where status = PENDING (HTTP 200)
- GET    /api/auctions/seller/{sellerId}
         Response: All auctions created by specific seller (HTTP 200)
- PUT    /api/auctions/{id}/approve
         Response: Auction status updated to ACTIVE (HTTP 200)
- PUT    /api/auctions/{id}/close
         Response: Auction status updated to SOLD or UNSOLD (HTTP 200)
- PUT    /api/auctions/{id}/terminate
         Response: Auction status updated to TERMINATED (HTTP 200)

6.3 BID CONTROLLER (`/api/bids`)
- POST   /api/bids
         Request: { "auctionId": 1, "userId": 2, "amount": 1500.00 }
         Response: Created Bid object (HTTP 200)
- GET    /api/bids/auction/{auctionId}
         Response: List of bids for auction ordered by amount DESC (HTTP 200)
- GET    /api/bids/user/{userId}
         Response: List of all bids placed by user ordered by bidTime DESC (HTTP 200)

6.4 ITEM CONTROLLER (`/api/items`)
- POST   /api/items
         Request: Item object (name, description, category, imageUrl)
         Response: Created Item with generated itemId (HTTP 200)
- GET    /api/items
         Response: List of all items (HTTP 200)
- GET    /api/items/{id}
         Response: Single item by ID (HTTP 200)

6.5 WATCHLIST CONTROLLER (`/api/watchlist`)
- POST   /api/watchlist?userId={userId}&auctionId={auctionId}
         Response: Created Watchlist entry (HTTP 200)
- DELETE /api/watchlist/{id}
         Response: HTTP 204 No Content
- GET    /api/watchlist/user/{userId}
         Response: List of user's watchlisted auctions with joined details (HTTP 200)

6.6 FILE UPLOAD CONTROLLER (`/api/upload`)
- POST   /api/upload
         Request: `multipart/form-data` with form field `file`
         Response: { "url": "http://localhost:8080/uploads/{uuid}.ext" } (HTTP 200)
- GET    /api/upload/local?path={absolute_local_path}
         Streams image files directly from user's hard drive to browser with appropriate MIME type.

7. EXCEPTION HANDLING & ERROR RESPONSES
================================================================================

The backend uses `GlobalExceptionHandler` (`@RestControllerAdvice`) to produce uniform JSON error responses:

Format:
{
  "timestamp": "2026-09-17T13:45:00.000Z",
  "status": 400,
  "error": "Bad Request",
  "message": "Bid must be higher than current price"
}

Exception Mappings:
- UserNotFoundException, ItemNotFoundException, AuctionNotFoundException -> HTTP 404 NOT FOUND
- EmailAlreadyExistsException, AlreadyInWatchlistException -> HTTP 409 CONFLICT
- InvalidCredentialsException, InvalidTokenException -> HTTP 401 UNAUTHORIZED
- SelfBidException, UnauthorizedActionException -> HTTP 403 FORBIDDEN
- BidTooLowException, AuctionNotActiveException, IllegalArgumentException -> HTTP 400 BAD REQUEST
- Generic Unhandled Exception -> HTTP 500 INTERNAL SERVER ERROR

2. Verify MySQL credentials in `src/main/resources/application.properties`:
   spring.datasource.url=jdbc:mysql://localhost:3306/bidearn

   spring.datasource.password=root

11.3 RUNNING THE BACKEND
Open a terminal in the project root (`d:/bidearn`):
- On Windows:
  ./mvnw.cmd spring-boot:run
- The backend server will start on: http://localhost:8080

Open a second terminal in `d:/bidearn/frontend`:
- Install dependencies:
  npm install
- Start the Vite development server:
  npm run dev
- The frontend will launch at: http://localhost:5173

- File Upload Endpoint (`/api/upload`):
  Saves uploaded multipart image files into the root `uploads/` folder with a unique UUID filename.
  Serves files statically via WebMvc resource handler at `/uploads/**`.
- Local Disk Streamer (`/api/upload/local?path=...`):
  Enables developers or testers to reference local images directly from disk paths without broken link errors.

12.3 PASSWORD ENCRYPTION
- Uses `BCryptPasswordEncoder` from `spring-security-crypto`.
- The user entity excludes the password from serialized JSON using `@JsonProperty(access = Access.WRITE_ONLY)`.
